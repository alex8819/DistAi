# Experimental patches (NOT applied by the build scripts)

Apply each one with `git -C native/llama.cpp apply native/patches-sperimentali/<name>.patch`. The patches that the build does apply are in `native/patches/`.

## vocab-subset.patch: reduced vocabulary for the logits
With `LLAMA_VOCAB_SUBSET=file` (one token id per line, generated by `tools/vocabsub.py`) the output layer multiplies only the rows of those tokens and puts the logits back
in place (`-inf` elsewhere).

**Result: not worth it for autoregressive decoding.** Qwen3-Coder-30B-A3B IQ2_XXS, 6 experts, i7 PC: 7.85 tok/s (full) → 7.96 (52,214 tokens, 34%) → 8.25 median (38,299 tokens, 25%, very noisy);
the prompt does not change. The estimate of +15% (output matrix = 23% of bytes read) was wrong: with 2-bit experts, dequantization compute dominates, not byte reads.
Coverage of the subset on unseen text (canonical tokens contained): Italian 98.9%, English 95.8%, code 92-99% with 34% of the vocabulary; with a character filter alone (66%) the loss is negligible but the saving is about 4%.
Worth retrying on a bandwidth-bound device (phone with dense Q4_0: estimated maximum +8%).

## bd3-cli.patch: `llama-bd3-cli`, block diffusion (BD3LM) with KV cache
Adds `examples/bd3` (and its line in `examples/CMakeLists.txt`): a BD3LM sampler on ggml for a standard `qwen2` GGUF (non-causal attention inside the block, finished blocks cached),
committing tokens above a confidence threshold. Android build: `native/build-diffusion-android.sh`.
Measurements and conclusions: see the diffusion sections of `NOTES.md` and `ROADMAP.md`. The reduced vocabulary does pay off here: -11% to -32% per step.

## rpc-stats.patch: per-command timings in the RPC server
`GGML_RPC_STATS=1 ggml-rpc-server ...` prints `RPC_STATS idle_ms=... COMMAND=n/ms ...` to stderr when the connection closes (time inside each handler plus time waiting for the client).
It separates compute (GRAPH_COMPUTE/RECOMPUTE), communication (COMM_ALLREDUCE, SET/GET_TENSOR) and waiting.
